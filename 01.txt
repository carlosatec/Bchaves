Aqui está o plano de engenharia detalhado, dividido em etapas lógicas e incrementais, para transformar a teoria "Quântica-Inspirada" em código C++ real no seu projeto. Como esse código vai espremer até a última gota dos registradores do processador, qualquer erro de ponteiro causará um Segmentation Fault.
Para garantir isolamento e evitar o congelamento do seu sistema principal durante os testes agressivos de memória e CPU, é altamente recomendável rodar essa compilação inicial dentro de um contêiner Docker ou provisionar temporariamente uma instância otimizada para computação na AWS (como a família c6i da Intel, que possui suporte nativo e massivo a AVX-512).
### Fase 1: Preparação do Ambiente e Infraestrutura Vetorial
Antes de tocar no algoritmo, precisamos garantir que o compilador e as estruturas de memória suportem registradores de 256 bits (AVX2) ou 512 bits (AVX-512).
 1. *Criação do Branch Experimental:* Nunca altere o address.cpp principal. Crie uma cópia chamada address_simd.cpp.
 2. *Flags de Compilação:* Altere o seu Makefile ou script de build para forçar o uso de instruções vetoriais e alinhamento de memória.
   * Adicione: -O3 -march=native -mavx512f -mavx512dq -mavx512vl (ou -mavx2 se sua CPU não suportar 512).
 3. *Alinhamento de Memória (Crítico):* Registradores AVX exigem que a memória seja alinhada em 32 ou 64 bytes. Se você passar um ponteiro normal para o AVX, ele quebra.
   * Modifique as alocações da sua struct de pontos (X, Y) para usar _mm_malloc(size, 64) em vez de malloc().
### Fase 2: Implementação do "Shor-Inspired Jump" (Saltos Cíclicos)
Vamos remover a soma linear simples (stride) e criar os saltos pseudo-aleatórios para garantir difusão perfeita pelo Range 71, evitando colisões entre as threads.
 1. *Tabela de Saltos (De Bruijn):* No início do programa (antes de abrir as threads), crie um array global contendo 65.536 valores de saltos pré-calculados usando uma sequência de De Bruijn ou números primos não-lineares.
   cpp
   uint32_t quantum_jumps[65536];
   // Preencher no main() com valores pseudo-aleatórios geométricos
   
   
 2. *Modificação na Thread:* Dentro do loop da thread_process_hybrid_chunk, localize onde a próxima chave é gerada.
   * *Remova:* A lógica linear (temp_stride.SetInt32(CPU_GRP_SIZE); key_mpz.Add(&temp_stride);).
   * *Insira:* Uma lógica que captura os últimos bits da chave atual para usar como índice na tabela de saltos, somando esse valor gigante à chave base. Isso simula o comportamento de difusão de Shor.
### Fase 3: Operações de Curva Elíptica Vetorial (AVX ECC)
Em vez de calcular uma coordenada X,Y por vez, vamos calcular 8 ou 16 simultaneamente.
 1. *Agrupamento Local:* Crie buffers locais alinhados dentro da thread para segurar 16 chaves privadas simultâneas.
 2. *Matemática SIMD:* Se você estiver usando a biblioteca secp256k1 original, ela não suporta AVX nativamente. Você precisará baixar ou adaptar os intrinsics de Point Addition em C++ (projetos como Cuda/OpenCL fazem isso, mas para CPU você precisará de macros _mm512_add_epi64, etc.).
 3. *Resultado:* Ao final desta etapa, você terá 16 pares de Coordenadas X e Y gerados exatamente no mesmo ciclo de processador.
### Fase 4: O Oráculo de Rejeição (SIMD SHA-256 + RIPEMD-160)
Aqui está o coração do Grover clássico. Não faremos hashes individuais.
 1. *Transposição de Matriz (O Segredo do AVX):* O algoritmo SHA-256 padrão consome blocos de 64 bytes de forma horizontal. O AVX-512 não funciona assim. Você precisa pegar os 16 pontos de curva elíptica gerados e *transpô-los* (transformar as linhas em colunas) para que o registrador de 512 bits carregue o "Bit 0" de todas as 16 chaves de uma vez.
 2. *Hashes Simultâneos:* Execute o código do SHA-256 totalmente reescrito com intrínsecos _mm512_xor_si512, _mm512_add_epi32. O mesmo deve ser feito para o RIPEMD-160.
 3. *A Máscara do Oráculo (Evitando extração):* No final do RIPEMD-160, os 16 endereços estarão dentro dos registradores. Não os descarregue para a memória RAM. Extrair do processador para a RAM é lento.
   * Carregue o alvo (o Endereço 71 convertido para RIPEMD160) em um registrador estático.
   * Faça um _mm512_cmpeq_epi32_mask comparando o registrador dos 16 resultados com o registrador do alvo.
   * *Se a máscara retornar 0 (nenhum bateu):* Pule o bloco inteiro imediatamente. Não acesse o Cuckoo Filter, não faça buscas binárias.
   * *Se a máscara retornar > 0:* Uma das 16 chaves é o Puzzle 71. Extraia o índice específico e salve a vitória.
### Fase 5: Monitoramento e Telemetria
Como o código agora trabalha em rajadas massivas vetoriais, o método clássico de printar no console a cada segundo vai gargalar o processador.
 1. *Variáveis Atômicas Relaxadas:* Mantenha a correção que fizemos no passo 1 do plano anterior usando std::memory_order_relaxed no steps_add.
 2. *Exportação de Métricas:* Configure o address_simd.cpp para gravar apenas uma métrica de hash/rate em um socket local ou arquivo em memória (/dev/shm).
 3. *Integração de Dashboards:* Capture essa métrica externa com um script simples, enviando os dados para o Zabbix. Montar um painel no Grafana conectado a esse agente permitirá monitorar em tempo real a curva de eficiência térmica da CPU e o impacto direto do AVX-512 na velocidade, sem poluir o terminal onde a execução principal ocorre.
*Ordem de Execução Recomendada:* Comece implementando e validando apenas a *Fase 2 (Shor Jump)* com a matemática clássica lenta. Depois que a estabilidade for confirmada (nenhuma chave perdida), migre para a *Fase 4 (SIMD Hash)* gerando chaves manuais para testar se os intrínsecos produzem o SHA-256 correto.
