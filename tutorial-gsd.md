# 🦾 Bíblia GSD: Guia Definitivo de Alta Performance

O framework **GSD (Get Shit Done)** é uma metodologia de engenharia assistida por IA. Este guia cobre desde os fundamentos até os comandos avançados para dominar o ciclo de desenvolvimento.

---

## 🚀 Cenário 1: O "Big Bang" (Projeto do Zero)

Inicie com estrutura e intenção. O segredo de um projeto de sucesso no GSD é o **Contexto Inicial**.

### 1. Nascimento do Projeto
- **Comando:** `/gsd-go gsd-new-project`
- **Dica de Ouro:** Não responda apenas "sim" ou "não". Forneça detalhes sobre as restrições (ex: "Sem bibliotecas externas", "Foco em latência DDR3").
- **Resultado:** Cria o `PROJECT.md`, a "Constituição" do seu projeto.

### 2. Engenharia de Requisitos (`gsd-spec-phase`)
- **Comando:** `/gsd-go gsd-spec-phase 1`
- **O que faz:** Realiza uma entrevista socrática para travar os requisitos **antes** de qualquer código.
- **Dica:** Use isso para evitar o "Scope Creep" (o projeto crescer sem controle).

### 3. O Ciclo Sagrado de Execução (Discuss → Plan → Execute)
Para cada funcionalidade no seu `ROADMAP.md`:
1.  **Discussão Técnica:** `/gsd-go gsd-discuss-phase --interactive`
    *   *Por que usar?* Para escolher entre algoritmos ou bibliotecas antes de planejar.
2.  **Planejamento Detalhado:** `/gsd-go gsd-plan-phase`
    *   *Resultado:* Gera um `PLAN.md` com passos atômicos.
3.  **Execução Massiva:** `/gsd-go gsd-execute-phase`
    *   *O que acontece:* A IA assume o controle e escreve o código em "ondas" paralelas.
4.  **Verificação Conversacional:** `/gsd-go gsd-verify-work`
    *   *Dica:* A IA vai te perguntar como testar cada item para garantir que nada quebrou.

## 🛠️ Cenário 2: O "Refactoring" (Projeto Existente)

Transforme um código legado em uma base de código moderna e auditada.

### 1. Inteligência e Mapeamento
- **Mapear Tudo:** `/gsd-go gsd-map-codebase` (Lê e documenta toda a arquitetura).
- **Scanner de Qualidade:** `/gsd-go gsd-scan --focus quality` (Encontra bugs e "smells").
- **Mapa de Conhecimento:** `/gsd-go gsd-graphify` (Cria grafos de como os arquivos se relacionam).
- **Consultar Inteligência:** `/gsd-go gsd-intel` (Pergunte qualquer coisa sobre o código: "Onde está o gargalo de memória?").

### 2. Auditoria e Limpeza
- **Auto-Fix:** `/gsd-go gsd-audit-fix --severity high` (Encontra e corrige problemas críticos sozinho).
- **Review de Segurança:** `/gsd-go gsd-secure-phase` (Verifica se as mudanças recentes criaram brechas).

## 🧠 Gestão de Ideias e Backlog (Não perca nada!)

O GSD permite capturar lampejos de gênio sem sair do código.

- **Notas Rápidas:** `/gsd-go gsd-note "Implementar cache L2 aqui"` (Cria uma nota persistente).
- **Estacionar Ideia:** `/gsd-go gsd-add-backlog "Suporte para ARM64"` (Manda para o fim do Roadmap).
- **Plantar Semente:** `/gsd-go gsd-plant-seed` (Anote uma ideia que só deve "brotar" quando certas condições forem atendidas).

## ⚡ Comandos de Controle Avançado

### Autonomia Total
- **Modo Autônomo:** `/gsd-go gsd-autonomous`
- **Flags:**
    *   `--interactive`: Para participar das decisões.
    *   `--to N`: Trabalha sozinho até a Fase N e para.
    *   `--only N`: Foca exclusivamente na Fase N.

### Segurança e Rollback
- **Desfazer cagada:** `/gsd-go gsd-undo` (Reverte commits de forma segura e mantém a integridade do planejamento).
- **Saúde do Projeto:** `/gsd-go gsd-health` (Verifica se os arquivos do GSD estão corrompidos ou dessincronizados).

### Multi-Tasking (Fluxos Paralelos)
- **Workstreams:** `/gsd-go gsd-workstreams`
- **Uso:** Crie um "workstream" para um bug urgente enquanto a IA trabalha em uma feature longa no outro.

## 📊 Relatórios e Visibilidade

- **Progresso Visual:** `/gsd-go gsd-progress` (O melhor comando para ver onde você está).
- **Estatísticas:** `/gsd-go gsd-stats` (Métricas de código, tempo e esforço).
- **Relatório de Sessão:** `/gsd-go gsd-session-report` (Gera um resumo do que foi feito hoje para você ou seu time).

---

## 💡 Top 5 Dicas de Ouro

1.  **O Contexto é sua Arma:** Se a IA estiver confusa, use o `gsd-map-codebase` novamente para atualizar a "visão" dela.
2.  **Reviews são Seguros:** Sempre use o `gsd-code-review` seguido do `gsd-code-review-fix`. É a forma mais rápida de ter código perfeito.
3.  **Use Threads:** Se um assunto ficar muito longo, use o `/gsd-go gsd-thread` para isolar o contexto.
4.  **UAT é Sagrado:** Nunca marque uma fase como concluída no Roadmap sem rodar o `gsd-verify-work`.
5.  **A IA é seu Par:** Trate o GSD como um "Pair Programming" de elite. Discuta a arquitetura no `discuss-phase` como se estivesse falando com um arquiteto sênior.
