# Phase 14: Cryptographic Precision & GLV Hardening Plan

## 1. Objective
Refactor and repair the Secp256k1 GLV endomorphism arithmetic in `core/secp256k1.cpp` to fix critical mathematical errors (eigenvalue typo and rounding overflow/incorrect constants) and resolve a symbol collision on `to_lower`.

## 2. Issues Identified
1. **Critical Bug - Typo in `kGLV_Lambda`**:
   The eigenvalue `kGLV_Lambda` constant in `core/secp256k1.cpp` has a typo: `5363AD4CC05C30E0A5261C028812645A122E22EA2081667870F197FBF390947` instead of the correct `0x5363ad4cc05c30e0a5261c028812645a122e22ea20816678df02967c1b23bd72`.
2. **Critical Bug - GLV Rounding Overflow & Incorrect Constants**:
   The `decompose_glv` function uses an unsafe 128-bit approximation of the division by $n$ (curve order) that overflows `unsigned __int128`, leading to incorrect rounding. It also uses incorrect lattice basis constants (`b11`, `b21`). As a result, the decomposed components $k_1$ and $k_2$ can exceed 128 bits (up to 254 bits), causing silently truncated/corrupted scalar multiplication in `multi_multiply_128`.
3. **Symbol Collision - Duplicate `to_lower`**:
   `to_lower` is declared and defined in both `core/secp256k1.hpp` / `core/secp256k1.cpp` and `core/hash.hpp` under the same namespace `bchaves::core`. This causes compilation and ODR (One Definition Rule) risks.

## 3. Execution Plan (Extremely Detailed Steps)

### Step 1: Remove Duplicate `to_lower` Utility
* **Goal**: Resolve namespace symbol collision.
* **Implementation**:
    1. Remove the declaration `std::string to_lower(const std::string& text);` from `core/secp256k1.hpp`.
    2. Remove the definition `std::string to_lower(const std::string& text)` from `core/secp256k1.cpp`.
    3. Ensure `system/cli.cpp` and other clients call `bchaves::core::to_lower` which resolves to the inline version in `core/hash.hpp`.

### Step 2: Correct GLV Constants
* **Goal**: Restore correct mathematical parameters.
* **Implementation**:
    1. Update the `kGLV_Lambda` constant in `core/secp256k1.cpp` to the correct value:
       ```cpp
       const BigInt kGLV_Lambda = parse_hex("5363AD4CC05C30E0A5261C028812645A122E22EA20816678DF02967c1b23bd72");
       ```
    2. Define correct lattice basis vectors:
       - $a_1 = \text{0x3086D221A7D46BCDE86C90E49284EB15}$
       - $b_1 = -\text{0xE4437ED6010E88286F547FA90ABFE4C3}$
       - $a_2 = \text{0x114CA50F7A8E2F3F657C1108D9D44CFD8}$
       - $b_2 = \text{0x3086D221A7D46BCDE86C90E49284EB15}$

### Step 3: Implement Exact Wide Arithmetic Helpers
* **Goal**: Prevent 128-bit overflow and allow exact Babai rounding of the 384-bit intermediate products.
* **Implementation**:
    1. Add the following internal static functions to `core/secp256k1.cpp`:
       - `mul_256_by_128`: Computes a 512-bit product of a 256-bit `BigInt` and a 128-bit `BigInt`, storing it in `uint64_t[8]`.
       - `add_256_to_wide`: Adds a 256-bit `BigInt` to a 512-bit array in place.
       - `divide_wide_by_256`: Performs exact binary long division of a 512-bit array by a 256-bit divisor (`BigInt`), returning a 256-bit `BigInt` quotient.

### Step 4: Rewrite `decompose_glv`
* **Goal**: Decompose any scalar $k \pmod n$ into $k_1, k_2$ bounded by $2^{128}$ exactly.
* **Implementation**:
    1. Compute $c_1 = \lfloor \frac{k \cdot b_2 + n/2}{n} \rfloor$ and $c_2 = \lfloor \frac{k \cdot |b_1| + n/2}{n} \rfloor$ exactly using the wide arithmetic helpers.
    2. Compute:
       - $k_1 = k - c_1 a_1 - c_2 a_2$
       - $k_2 = c_1 |b_1| - c_2 b_2$
    3. Determine the absolute values and signs of $k_1, k_2$ and return them via reference arguments.

### Step 5: Write the Cryptographic Regression Test Suite
* **Goal**: Validate correctness of the new GLV pipeline and general EC operations.
* **Implementation**:
    1. Create a new test file `tests/crypto_test.cpp` containing verification blocks for:
       - Curve point addition and doubling.
       - Endomorphism relation check $\phi(P) = \lambda P$.
       - Decomposing $10,000$ random scalars and asserting:
         - $k_1 + \lambda k_2 \equiv k \pmod n$
         - $|k_1| < 2^{128}$ and $|k_2| < 2^{128}$
       - Scalar multiplication parity: `secp256k1_multiply_glv(k) == secp256k1_multiply(k)`.
