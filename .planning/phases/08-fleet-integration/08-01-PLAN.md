# Phase 08-01: Fleet Batching Integration

## 🎯 Objetivo
Transformar o motor Kangaroo de um modelo de processamento escalar para um modelo de processamento vetorial (SIMD) em massa, utilizando lotes de pontos (Fleet) para maximizar o throughput em arquiteturas x86_64 e ARM64.

## 🏗️ Arquitetura de Lotes
- **Batch Size:** 1024 pontos (configurável via TuneProfile).
- **Layout:** SoA (Structure of Arrays) para carregamento direto em registros SIMD.
- **Normalization:** Montgomery Batch Inversion (1 inversão modular por lote).
- **Dispatching:** Uso do `FleetDispatcher` para seleção dinâmica do backend (SSE4/AVX2/AVX512/NEON).

## 📋 Passos de Execução

### 1. Refatoração de Dados
- [ ] Modificar `KangarooWorkerState` em `engine/kangaroo.cpp` para armazenar vetores de pontos Jacobianos.
- [ ] Implementar as funções `pack_fleet` e `unpack_fleet` para converter entre o formato de memória e os registros SIMD.

### 2. Implementação do Loop Vetorial
- [ ] Criar o loop de processamento em lote no `KangarooWorker`.
- [ ] Integrar chamadas para os kernels de adição de pontos SIMD (`point_add_*`).
- [ ] Implementar a lógica de detecção de "Distinguished Points" em massa usando máscaras SIMD.

### 3. Otimização Matemática
- [ ] Implementar a função `batch_invert_fleet` para normalização simultânea de todos os pontos do lote.
- [ ] Otimizar o acesso à tabela de saltos (Jump Table) para evitar conflitos de cache durante a vetorização.

### 4. Validação e Benchmarking
- [ ] Verificar a integridade do algoritmo comparando os resultados vetoriais com a implementação escalar.
- [ ] Executar benchmark contra o alvo (Puzzle #135) buscando throughput > 6 M/s.

## 🧪 Critérios de Aceitação (UAT)
1. O motor deve compilar sem erros em todos os backends SIMD.
2. O throughput deve aumentar em pelo menos 1.5x - 3x em relação à versão escalar.
3. Todas as colisões (armadilhas) devem ser detectadas corretamente e persistidas em disco sem corrupção.

## ⚠️ Riscos & Mitigações
- **Registro Pressure:** O compilador pode ter dificuldade em gerenciar registros com SoA grande. *Mitigação:* Usar inline helpers agressivos e limitar o tamanho dos blocos de processamento.
- **Divergência de Threads:** Alguns cangurus podem terminar antes de outros. *Mitigação:* Estratégia de "Kangaroo Recycling" para manter as pistas SIMD sempre cheias.
