# Phase 13: Hybrid & Kangaroo Optimization Plan

## 1. Objective
Refactor and optimize the Address Mode (Hybrid Search) and Kangaroo Engine to fix critical checkpoint synchronization issues and introduce advanced SIMD vectorization throughput enhancements.

## 2. Issues Identified
### Address Mode (Hybrid)
1. **Critical Bug - Checkpoint Gap**: The hybrid checkpoint relies on an inherently flawed heuristic: `checkpoint = done - num_threads`. Since thread execution is non-deterministic, slow threads can cause chunks to be permanently skipped upon resuming from a crash.
2. **Performance Bottleneck - Endianness scalarization**: The 32-byte endianness flip during batch creation relies on iterative `__builtin_bswap64`, limiting payload assembly speed.
3. **Performance Bottleneck - Filter Pipeline Bubble**: Under-filled batches (`batch_count < 8`) fallback to slow scalar hash lookups, creating pipeline bubbles instead of padding and feeding the AVX/SSE units consistently.

### Kangaroo Mode
1. **Critical Bug - State Desync on Exit**: The local fleet state is only synchronized with the global worker state every 102,400 hops. If an interrupt (SIGINT) occurs, the last synchronized state is saved, but `total_hops` includes the aborted hops, permanently decoupling metric telemetry from the mathematical state.
2. **Critical Bug - Data Race in Cuckoo Filter**: The core `AdaptiveCuckooFilter::insert()` is inherently NOT thread-safe, modifying buckets and counting without atomics or mutexes. However, Kangaroo workers currently invoke it concurrently, causing a catastrophic data race and memory corruption risk during cuckoo displacements.
3. **Performance Bottleneck - Lock Contention & Cache Thrashing**: When a Distinguished Point (DP) is found, the thread halts SIMD processing to perform Cuckoo filter lookups and take locks (`shard.mtx`). Multi-core collisions over DP discovery cause severe mutex contention.

## 3. Execution Plan (Extremely Detailed Steps)

### Step 1: Hybrid Checkpoint Synchronization Rewrite
* **Goal**: Ensure 100% chunk processing coverage with no missed keys across interruptions.
* **Implementation**:
    1. Replace `g_chunk_counter` derived checkpoint logic with a robust tracking array.
    2. Add `std::atomic<uint64_t> g_active_chunks[MAX_THREADS]` initialized to a sentinel value (e.g., `UINT64_MAX`).
    3. Modify worker loop: Before taking a chunk, the thread registers its chunk ID in `g_active_chunks[thread_id]`.
    4. Upon chunk completion, the thread unsets the chunk ID.
    5. In the checkpoint logic (main loop), compute `safe_checkpoint_id` as the MINIMUM of `g_chunk_counter` and all currently active chunks in `g_active_chunks`. This perfectly defines the exact *low-water mark*.
    6. Update `system/checkpoint.hpp` and `system/checkpoint.cpp` structures if necessary.

### Step 2: Kangaroo Emergency Sync Fix
* **Goal**: Prevent loss of fleet progress and `total_hops` drift on SIGINT.
* **Implementation**:
    1. Inside `engine/kangaroo.cpp` `worker` lambda, place a mandatory state synchronization block immediately after the `while(!g_stop_requested...)` loop exits.
    2. Lock `worker_state.mutex` and copy `local_fleet.x/y/z/d` back to `worker_state.fleet`.
    3. Ensure `total_hops` exactly matches the hops of the saved fleet state by decoupling `fetch_add` or recalculating accurately during the snapshot phase.

### Step 3: Hybrid Engine Vectorization & Pipeline Flattening
* **Goal**: Maximize throughput of payload generation and filter hashing while preserving multi-arch portability.
* **Implementation**:
    1. Implement a branchless vector endianness swap inside `core/simd_hashing.hpp` using conditional compilation (`#if defined(__AVX2__)` using `_mm256_shuffle_epi8`, `#elif defined(__SSSE3__)` using `_mm_shuffle_epi8`, and `#elif defined(__aarch64__)` using NEON `vqtbl1q_u8`).
    2. Maintain the existing `__builtin_bswap64` as a fallback in the core header to ensure cross-platform compatibility for CPUs lacking advanced SIMD.
    3. Modify the batching logic: Always force `check_batch_fn` to process in powers of 8. If `lane_count < 8`, pad the remaining buffer spaces with duplicate data from `lane_count - 1` and ignore the extra results, removing the scalar loop fallback path entirely.

### Step 4: Kangaroo Thread-Local Queue & Safe Filter Insertion
* **Goal**: Fix Cuckoo Filter data race (UB on concurrent lookups/inserts) and eliminate locking overhead in the SIMD hot loop.
* **Implementation**:
    1. Introduce a new global `std::mutex filter_mtx` to protect ALL `AdaptiveCuckooFilter` operations (both `lookup` and `insert`) in Kangaroo mode.
    2. Inside `local_fleet` processing, create a lightweight array-based queue `TrapKey local_dps[64]`.
    3. Change the SIMD hit loop (`PROCESS_DISTINGUISHED_POINT`) to purely append the extracted DP into `local_dps` without touching shared states.
    4. When `local_dps` fills up (or at batch end), batch process the queue:
        * First, lock `filter_mtx` and execute all `lookup` and `insert` operations on the CuckooFilter, storing the result (hit or miss). Unlock `filter_mtx` immediately to minimize critical section.
        * Second, iterate over the results and lock the respective `shard.mtx` to perform the actual trap table insertions or collision checks.
    5. This resolves the Data Race, prevents Mutex Deadlocks (by avoiding nested locks), and isolates SIMD from memory latency.

### Step 5: Test & UAT Validation
* **Goal**: Verify engine stability and data integrity.
* **Implementation**:
    1. Force a SIGINT kill using a test script during Address Hybrid mode and verify exact chunk continuity on resume.
    2. Test Kangaroo memory boundaries and checkpoint validity ensuring no drift occurs.
    3. Run benchmark scripts against standard testnet keys to quantify the SIMD improvements.
