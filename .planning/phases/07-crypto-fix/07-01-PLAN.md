# Phase 7 Plan: Fix Critical Crypto Implementation Issues

## Objective
Fix all critical issues from phase 6 verification and code review in the secp256k1 SIMD implementations.

**Purpose:** The SIMD implementations have fundamental bugs that cause incorrect cryptographic results. These must be fixed to ensure the engine produces correct outputs.

**Output:** Fixed `core/secp256k1-arm64.cpp`, `core/secp256k1-sse4.cpp`, `core/secp256k1-avx2.cpp`, `core/secp256k1-avx512.cpp` with proper modular multiplication and point addition.

## Tasks

### Task 1: Fix ARM64 64-bit Modular Multiplication
**Files:** `core/secp256k1-arm64.cpp`

**Implementation:**
1. Replace the broken 32-bit multiply with proper 128-bit multiplication using ARM64 intrinsics:
   - Use `vmul_s64` for low 64-bit (a * b)
   - Use `vmulh_s64` for high 64-bit ((a * b) >> 128)
   - Combine low and high into 128-bit result

2. Implement secp256k1 prime P reduction:
   - P = 2^256 - 2^32 - 977
   - Use the specialized fast reduction from secp256k1.cpp: `reduce_p256_64()`
   - Since NEON doesn't have 128-bit intermediate, do reduction in two steps

3. Verify with test vectors:
   - 1 * 1 = 1
   - (P-1) * (P-1) = 1 (since (P-1)^2 = 1 mod P)
   - Random values against portable implementation

**Expected result:**
```cpp
inline uint64x2_t mul_mod_arm64(uint64x2_t a, uint64x2_t b) {
    // Get low 64-bit of 64x64 multiply
    uint64x2_t lo = vmul_s64(a, b);
    // Get high 64-bit of 64x64 multiply (umulh)
    uint64x2_t hi = vmulh_s64(a, b);
    // Now combine lo/hi and reduce mod P
    // ... implement reduction
}
```

**Verification:** Compile with `-march=armv8-a+crc+crypto` and verify output matches portable implementation

### Task 2: Fix SSE4 64-bit Modular Multiplication
**Files:** `core/secp256k1-sse4.cpp`

**Implementation:**
1. Replace `_mm_mul_epu32` (32-bit) with proper 64-bit multiplication:
   - SSE4.1 doesn't have 64-bit PMULL, use two 32-bit products instead
   - Or use `__m128i` to hold two 64-bit values and compute full product

2. Implement approach using two 32-bit multiplies per 64-bit:
   - `(a_lo * b_lo) + ((a_lo * b_hi + a_hi * b_lo) << 32) + (a_hi * b_hi << 64)`
   - This requires extracting 32-bit halves

3. Add modulo reduction for secp256k1 prime P

**Alternative - Use inline assembly:**
```cpp
inline __m128i mul_mod_sse4(__m128i a, __m128i b) {
    __m128i result;
    __asm__ {
        movdqu xmm0, a
        movdqu xmm1, b
        pshufd xmm2, xmm0, 0x0E  // swap 64-bit halves
        pshufd xmm3, xmm1, 0x0E
        pmuludq xmm0, xmm1       // low * low (64-bit result)
        pmuludq xmm2, xmm3       // high * high (64-bit result)
        // ... combine and reduce
    }
}
```

**Verification:** Compile with `-msse4.1` and verify against secp256k1.cpp

### Task 3: Fix AVX2 Modular Multiplication with Reduction
**Files:** `core/secp256k1-avx2.cpp`

**Implementation:**
1. Current `_mm256_mullo_epi64` only gives low 64-bit of 64x64 multiply
2. Need to use `_mm256_mul_epu32` pairs or custom reduction:
   - Extract 32-bit lanes, compute 64-bit products, combine

3. Implement secp256k1 P reduction using carry-less approach:

   - Then propagate carries

**Verification:** Compile with `-mavx2` and verify output

### Task 5: Implement Real Point Addition for All Backends
**Files:** `core/secp256k1-arm64.cpp`, `core/secp256k1-sse4.cpp`, `core/secp256k1-avx2.cpp`, `core/secp256k1-avx512.cpp`

**Implementation:**
The point_add functions currently just return p2. For batching to work properly, implement actual point addition:

For Jacobian coordinates (P = X/Z^2):
1. Compute: U1 = X1 * Z2^2, U2 = X2 * Z1^2
2. Compute: S1 = Y1 * Z2^3, S2 = Y2 * Z1^3
3. If U1 == U2: check S1 == S2 for point doubling, else return infinity
4. Compute: H = U2 - U1, R = S2 - S1
5. Result: X3 = R^2 - H^3 - 2*U1*H^2, Y3 = R*(U1*H^2 - X3) - S1*H^3, Z3 = Z1*Z2*H

**Simplified for batching (add to infinity check):**
- If p1.z == 0: return p2
- If p2.z == 0: return p1

**Verification:** Test with known point addition pairs
