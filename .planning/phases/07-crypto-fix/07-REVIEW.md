### 🔴 CRITICAL

#### 1. Missing Modular Reduction in All SIMD Backends
**Files:** `core/secp256k1-sse4.hpp`, `core/secp256k1-avx2.hpp`, `core/secp256k1-avx512.hpp`, `core/secp256k1-arm64.hpp`
**Description:** The `mul_mod_*` functions (e.g., `mul_mod_sse4` at lines 63-77) compute partial products into an 8-limb accumulator (`acc[8]`) but then simply truncate the result to the lower 4 limbs without any modular reduction.
```cpp
// From core/secp256k1-sse4.hpp:75-76
// Simplificado: r = acc[0..3] (Falta a redução real mod P completa)
for(int i=0; i<4; ++i) r[i] = acc[i];
```
**Impact:** Cryptographic operations will produce incorrect results for any values whose product exceeds $2^{256}$. This renders the entire SIMD engine useless for actual search.

#### 2. Lack of Carry Propagation in `mul64x64_full` (SSE4/AVX2)
**Files:** `core/secp256k1-sse4.hpp`, `core/secp256k1-avx2.hpp`
**Description:** The 64x64 multiplication implementation fails to handle the carry bit when adding the `mid_lo` part to the `ll` part.
```cpp
// From core/secp256k1-sse4.hpp:51-53
// Carry: se r_lo < mid_lo, houve carry. 
// Para esta versão, a implementação robusta de carry foi omitida para garantir compilação.
```
**Impact:** Mathematical errors in the low 64 bits of every limb multiplication.
