## 🎯 Implementation Strategy

### 1. ARM64 Multiplication (umulh)
- **Decision:** Use "Pure SIMD" approach.
- **Rationale:** Avoids switching between scalar and vector pipelines.
- **Details:** Split 64-bit operands into 32-bit halves. Use `vmull_u32` for 32x32 -> 64 multiplications and combine results with carry handling to simulate a 128-bit product.

### 2. Modular Reduction Architecture
- **Decision:** Implement as a template-based header `core/secp256k1_reduce.hpp`.
- **Rationale:** Ensures DRY (Don't Repeat Yourself) principle while allowing compiler-specific optimizations (AVX, NEON) via template specialization.
- **Details:** The primary reduction logic for the Secp256k1 prime (2^256 - 2^32 - 977) will be shared across all SIMD backends.

### 3. Point Addition Fidelity
- **Decision:** Full Jacobian Point Addition.
- **Rationale:** Reliability is critical for long-running Kangaroo searches.
- **Details:** Implement the complete formula for Jacobian coordinates, including handling for point-at-infinity and potential identity cases.
