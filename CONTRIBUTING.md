# 🤝 Contributing to Bchaves

Thank you for your interest in contributing to **Bchaves**! Whether you are fixing bugs, improving performance, or adding new features, your help is welcome.

## 📜 Code of Conduct
This project expects all contributors to maintain a professional and respectful environment.

## 🛠️ Getting Started
1. **Fork** the repository on GitHub.
2. **Clone** your fork locally.
3. Create a **feature branch** (`git checkout -b feature/amazing-optimization`).
4. **Build** the project to ensure everything is working: `make all`.

## 💻 Contribution Guidelines

### Performance First
Bchaves is a performance-critical engine. Any changes to the `core/` or `engine/` directories should be benchmarked:
- Run a benchmark before and after your changes.
- Provide the results (Keys/s and CPU usage) in your Pull Request.

### Code Style
- Follow the existing **snake_case** (functions/vars) and **PascalCase** (types) convention.
- Use 4 spaces for indentation.
- Keep the `core/` directory free of heap allocations in the hot loop.

### Testing
- Run `make test && ./build/crypto_test` to verify your changes haven't broken the cryptographic kernel.
- Add new tests if you are introducing new math or hashing logic.

## 📬 Submitting a Pull Request
1. **Push** your changes to your fork.
2. Open a **Pull Request** against the `main` branch of the original repository.
3. Describe your changes in detail:
    - What problem does it solve?
    - How did you test it?
    - What is the performance impact?
