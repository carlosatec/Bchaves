# ⚙️ Configuration Guide

This document provides a detailed reference for all command-line parameters and configuration options available in **Bchaves**.

## 🚀 Common Search Parameters

These parameters are applicable across most search modules (`address`, `bsgs`, `kangaroo`).

### Range and Targets
- **`-b <bits>`**: Specifies the bit range for the search (e.g., `-b 65`). For the `address` module, this defines the search space relative to a fixed start point. For `kangaroo`, it automatically calculates the range $[2^{b-1}, 2^b - 1]$.
- **`targets.txt`**: The first positional argument is always the path to a file containing target addresses or public key hashes (one per line).

### Performance Tuning
- **`-t <threads>`**: Manually sets the number of processing threads. If omitted, the engine defaults to the strategy defined by `-A`.
- **`-A <profile>`**: **Auto-Tune** profile selection.
    - `safe`: Uses half of the physical cores. Ideal for background tasks.
    - `balanced`: (Default) Uses all physical cores.
    - `max`: Uses all logical cores (Hyper-Threading). Recommended for dedicated mining rigs.
- **`-k <multiplier>`**: Chunk size multiplier. Defines how many keys are processed in a single batch before updating progress.
    - `1024`: ~1 million keys per batch. Good for ranges < 60 bits.
    - `4096`: ~4 million keys per batch. Recommended for ranges 70-80 bits.
    - `8192`: ~8 million keys per batch. Best for ultra-high range searches (80+ bits) to minimize ECC overhead.

## 📍 Address Engine Specifics (`build/address`)

- **`-R <mode>`**: Search strategy.
    - `hybrid`: (Recommended) Partitioned pseudo-random explorer with 100% coverage.
    - `sequential`: Linear search from start to end.
- **`-l <type>`**: Address compression filter.
    - `compress`: Only search for compressed WIFs.
    - `uncompress`: Only search for uncompressed WIFs.
    - `both`: Search both (doubles effective search speed per key but halves keys/s).

## 🦘 Kangaroo Engine Specifics (`build/kangaroo`)

- **`--trap-dir <dir>`**: Directory to store "traps" (jump points). Defaults to `traps/`.
- **`--wild <N>`**: Percentage of wild kangaroos (Default: 50).
- **`--tame <N>`**: Percentage of tame kangaroos (Default: 50).
- **`--no-load`**: Skips loading existing traps from disk (*Cold Boot*). Useful for quick benchmarks.

## 📉 Persistence and Checkpoints

- **`-c <path>`**: Explicitly defines the path for the checkpoint file.
- **`--benchmark`**: Runs the engine without saving checkpoints or logging found keys. Used for performance testing.

## 🛡️ Backend and Optimizations

- **`--secp256k1-backend <auto|portable>`**:
    - `auto`: Uses the most optimized kernel (AVX2/ARM Crypto).
    - `portable`: Forces plain C++ implementation.
- **`--no-endo`**: Disables GLV endomorphism optimization (useful for debugging).
- **`--list-hardware`**: Shows detected CPU features (AVX2, BMI2, etc.) and exits.
