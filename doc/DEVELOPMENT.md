# 🛠️ Development Guide

This guide is for developers looking to contribute to **Bchaves** or build specialized versions of the engine.

## 🏗️ Building from Source

### Build Targets
The `Makefile` supports several targets:
- `make all`: Builds all search engines (`address`, `bsgs`, `kangaroo`).
- `make address`: Builds only the address search engine.
- `make bsgs`: Builds only the BSGS engine.
- `make kangaroo`: Builds only the Kangaroo engine.
- `make test`: Builds the cryptographic test suite.
- `make clean`: Removes the `build/` directory.

### Environment Variables
- `CXX`: Define the C++ compiler (default: `g++`).
- `CXXFLAGS`: Override default flags (default: `-std=c++17 -O3 -flto`).

## 🧬 Project Architecture

Bchaves is organized into three main layers:

1. **`core/`**: Low-level primitives.
    - `secp256k1`: ECC arithmetic.
    - `hash`: SHA256 and RIPEMD160 implementations.
    - `cuckoo`: Probability filters.
2. **`engine/`**: High-level search algorithms.
    - Orchestrates threads, batching, and target matching.
3. **`system/`**: Platform-specific utilities.
    - Hardware detection, CLI parsing, and I/O.

## 🧪 Testing

We use a custom test runner for cryptographic verification. It is essential to run this after any changes to the `core/` directory.

```bash
make test
./build/crypto_test
```

### Adding New Tests
Add new test cases to `tests/crypto_test.cpp`. Focus on:
- Boundary conditions for modular reduction.
- Point addition and doubling consistency.
- Correctness of GLV decomposition.

## 🚀 Performance Profiling

To profile the engine:
1. Compile with symbols: `CXXFLAGS="-g -O3" make all`.
2. Use `perf` (Linux) or `VTune`:
   ```bash
   perf record -g ./build/address targets.txt -b 65 --benchmark
   perf report
   ```

## 📜 Coding Standards
- Use **snake_case** for functions and variables.
- Use **PascalCase** for classes and structs.
- Prefer **RAII** and smart pointers over manual memory management.
- Ensure all new features are compatible with both **x86_64** and **ARM64**.
