# 🧪 Testing and Quality Assurance

**Bchaves** employs a multi-layered testing strategy to ensure cryptographic correctness and high-performance search reliability.

## 🧮 Cryptographic Verification

The core of the engine is tested against known constants and edge cases for the Secp256k1 curve.

### Running the Test Suite
```bash
make test
./build/crypto_test
```

### Coverage
The `crypto_test` suite covers:
1. **Field Arithmetic**: Addition, subtraction, multiplication, and modular inversion in the Secp256k1 field.
2. **Point Operations**: Affine and Jacobian point addition, doubling, and scalar multiplication.
3. **GLV Decomposition**: Verification that scalars are correctly split into $k_1, k_2$ components for faster multiplication.
4. **Hashing**: SHA-256 and RIPEMD-160 validation against official test vectors.
5. **Address Generation**: P2PKH address derivation from public keys (compressed and uncompressed).

## 📊 Benchmarking

Performance is a first-class citizen. Use the `--benchmark` flag to measure your system's throughput without writing to disk.

```bash
# Benchmark the Address Engine (Hybrid mode)
./build/address targets.txt -b 65 -R hybrid --benchmark
```

### Key Metrics
- **Keys/s**: Number of unique private keys explored per second.
- **Checks/s**: Total number of address comparisons performed.
- **Batch Latency**: Time taken to process a single `-k` chunk.

## 🛡️ Hardware Verification

### Checkpoint Integrity
We verify that searches can be paused and resumed without skipping keys or losing progress.
1. Start a search: `./build/address targets.txt -b 65 -R hybrid`.
2. Stop after a few minutes (`Ctrl+C`).
3. Note the last processed key.
4. Resume and verify the engine starts exactly from the saved state.

### Hardware Detection Validation
Verify hardware detection works correctly on all supported platforms:
```bash
./build/address --list-hardware
```

Expected output includes:
- CPU vendor, family, model
- Physical and logical core counts
- L1, L2, L3 cache sizes
- Total RAM and memory channels
- SIMD feature flags (SSSE3, SSE4, AVX, AVX2, AVX512, SHA-NI, BMI2, NEON)
- Detected ISA level
- NUMA status

### ISA-Specific Testing
Test on different architectures to verify ISA-aware optimizations:
- **x86_64**: Intel Xeon, AMD Ryzen (test AVX2, AVX512 paths)
- **ARM64**: Apple M1/M2/M3, Raspberry Pi 5, Oracle Ampere (test NEON paths)

## 🔍 Continuous Improvement

We are working towards integrating standard frameworks like **GTest** for more granular unit testing and **AddressSanitizer** for memory safety verification in the high-level engine logic.
